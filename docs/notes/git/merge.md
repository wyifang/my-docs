# Git 合并与冲突

## 1. 什么是合并？

合并（merge）是把一个分支的修改整合到另一个分支中。

例如：在 `feature` 分支完成新功能后，可以把它合并到 `main`。

## 2. 快进合并（Fast-forward）

如果 `main` 在分支创建后没有新的提交，Git 通常可以直接把 `main` 指针向前移动。

```bash
git switch main
git merge feature
```

这种情况通常不需要创建额外的合并提交。

## 3. 三方合并（Three-way merge）

如果两个分支从共同的提交之后都产生了新的提交，Git 通常会进行三方合并。

```bash
git switch main
git merge feature
```

Git 会根据共同祖先以及两个分支的变化尝试整合修改。根据具体情况，可能创建一个合并提交。

## 4. 什么是合并冲突？

当 Git 无法自动判断如何整合不同分支的修改时，就会产生合并冲突。

例如，两个分支修改了同一文件中的同一段内容。

冲突标记通常类似这样：

```text
<<<<<<< HEAD
main 分支中的内容
=======
feature 分支中的内容
>>>>>>> feature
```

* `<<<<<<< HEAD` 到 `=======`：当前分支的内容
* `=======` 到 `>>>>>>> feature`：待合并分支的内容

## 5. 解决冲突的基本步骤

1. 查看 Git 提示，确认哪些文件有冲突。
2. 打开冲突文件，理解双方的修改。
3. 手动编辑，保留正确内容，并删除冲突标记。
4. 暂存解决后的文件。
5. 完成合并提交（如果 Git 要求）。

常用命令：

```bash
git status
git add <文件名>
git commit
```

如果想放弃当前这次合并，可以使用：

```bash
git merge --abort
```

该命令用于尝试恢复合并前的状态；执行前仍应留意未提交的修改。

## 6. 合并前的检查

```bash
git status
git branch
```

确认当前分支、工作区状态以及准备合并的目标分支，再执行合并。
