# RAG（检索增强生成）

## 一、什么是 RAG？

RAG 是 Retrieval-Augmented Generation 的缩写，中文通常称为“检索增强生成”。

它是一种让大语言模型在回答问题前，先从外部知识源检索相关信息，再结合检索结果生成回答的方法。

例如，企业可以把产品手册、内部技术文档和常见问题整理成知识库。用户提问时，系统先检索相关内容，再将这些内容提供给大语言模型作为回答依据。

## 二、为什么需要 RAG？

大语言模型并不天然掌握企业所有最新、私有的知识。RAG 可以帮助应用：

- 利用企业内部或特定领域的知识。
- 为回答提供相关的外部资料。
- 在知识更新时，通过更新知识库减少对重新训练模型的依赖。
- 在适当的实现中提供来源引用，便于用户核查答案。

需要注意：RAG 不能保证回答一定正确，也不能自动消除模型幻觉。检索质量、文档质量和生成过程都会影响最终结果。

## 三、RAG 的基本工作流程

1. **准备知识**：收集并解析文档。
2. **切分文档**：将文档整理成适合检索的文本片段。
3. **建立索引**：生成向量表示，并保存向量及相关元数据。
4. **接收问题**：获取用户的问题，必要时进行查询改写。
5. **检索内容**：从知识库中找出相关片段。
6. **生成回答**：将问题和检索结果一起交给大语言模型。
7. **评估结果**：检查答案的相关性、准确性和来源依据。

## 四、RAG 涉及的核心技术

### 文档解析与切分

将 PDF、网页、Markdown 等来源转换成可处理的内容，再切分为适合检索的片段。

### Embedding（向量嵌入）

将文本转换成数值向量，使系统能够根据语义相似性寻找相关内容。

### 向量检索

根据查询向量搜索相似的文档片段。实际系统也可能结合关键词检索或混合检索。

### Reranking（重排序）

对初步检索结果再次排序，让更相关的内容优先进入生成阶段。

### 大语言模型生成

模型结合用户问题和检索到的内容生成回答。提示词设计、上下文长度和来源质量都会影响输出。

## 五、RAG 与 AI 数据基础设施的关系

RAG 不只是调用大语言模型。它还需要可靠的数据处理、存储、索引和检索能力。

在实际系统中，数据基础设施可以支持：

- 原始文档的存储与管理。
- 文档解析、清洗和更新。
- 向量及元数据的存储。
- 检索与数据访问。
- 数据版本管理和质量评估。

不同系统的具体架构有所不同，RAG 并不要求一定使用某一种数据库或数据湖产品。

## 六、实践练习

选择一份自己熟悉的技术文档，思考以下问题：

1. 文档需要经过哪些处理才能用于 RAG？
2. 应该如何切分文档，才能保留标题和上下文？
3. 如何判断检索到的片段是否真正回答了用户问题？
4. 如何让回答引用对应的文档来源？
5. 如果文档更新，系统应如何同步更新索引？

## 七、后续学习

后续可以继续深入文档切分、Embedding、向量检索、混合检索、重排序和 RAG 评估，并通过小型知识库项目验证这些概念。
