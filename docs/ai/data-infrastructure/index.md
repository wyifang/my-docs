# AI 数据基础设施

AI 数据基础设施关注如何存储、管理、处理和检索数据，为大语言模型、RAG、Agent 及其他 AI 应用提供可靠的数据能力。

本页面将从数据湖与 Lakehouse 出发，逐步理解向量数据、多模态数据和 AI 应用之间的关系。

## 一、为什么 AI 应用需要数据基础设施？

大语言模型本身并不等于完整的 AI 应用。实际应用往往还需要访问外部知识、处理不同格式的数据、更新数据索引，并控制数据访问权限。

例如，一个企业技术文档助手可能需要：

- 存储 PDF、Markdown、网页等文档。
- 解析文档并保留标题、段落和元数据。
- 将文档切分成适合检索的内容片段。
- 为文本生成向量表示。
- 根据用户问题检索相关内容。
- 将检索结果交给大语言模型生成回答。
- 在文档更新后同步更新相关索引。

这些工作涉及数据存储、数据处理、索引、查询和治理等能力。

## 二、Data Lake（数据湖）

数据湖是一种用于存储多种类型数据的数据架构，可以保存结构化、半结构化和非结构化数据。

在 AI 场景中，数据湖可以用于保存：

- 原始业务数据。
- 技术文档与其他文件。
- 多模态数据及其相关元数据。
- 数据处理过程中产生的中间结果。

数据湖提供数据存储基础，但仅有数据湖并不意味着系统已经具备完整的 AI 检索和推理能力。

## 三、Lakehouse（湖仓一体）

Lakehouse 通常希望结合数据湖的灵活存储能力与数据仓库常见的数据管理、查询和治理能力。

在具体实现中，Lakehouse 可以支持数据组织、表管理、事务一致性、数据处理和分析查询等功能，但不同产品的能力存在差异。

对于 AI 应用，Lakehouse 可以帮助管理和处理用于训练、分析、检索或其他 AI 工作流的数据。

## 四、向量数据与向量检索

### Embedding（向量嵌入）

Embedding 模型可以将文本、图像等输入转换成数值向量，以便系统执行相似性搜索等操作。

### 向量检索

向量检索根据查询向量与已存储向量之间的相似程度，寻找可能相关的数据。

实际系统可能结合关键词检索、元数据过滤和重排序，以提高检索效果。

### 向量数据库

向量数据库通常提供向量存储、相似性搜索和相关的数据管理能力。不同产品在过滤、索引、扩展性和其他功能方面存在差异。

需要注意：向量检索是一种检索能力，并不等同于 RAG。RAG 还需要将检索结果与大语言模型的生成过程结合起来。

## 五、多模态数据

多模态 AI 涉及文本、图像、音频、视频等不同类型的数据。

实际系统需要根据任务处理相应的数据格式、元数据、特征表示和检索方式。并不是所有多模态系统都使用相同的存储结构或索引方法。

例如，技术支持系统可能需要检索文本手册中的说明，也可能需要查找与某个设备相关的图片。

## 六、AI 数据基础设施与 RAG 的关系

一个简化的 RAG 流程可以表示为：

1. 将原始文档存储在合适的数据系统中。
2. 解析并切分文档。
3. 生成 Embedding 并建立索引。
4. 接收用户问题并执行检索。
5. 将相关内容交给大语言模型。
6. 生成回答并检查来源依据。

数据湖、Lakehouse、向量数据库及其他存储系统可能在不同环节发挥作用，但它们并不是互相替代的同义词。

具体架构需要根据数据规模、查询方式、性能要求、数据治理和产品能力设计。

## 七、与 Agent 和 MCP 的关系

### 与 Agent

Agent 可以围绕目标执行多个步骤，并在需要时使用数据检索或其他工具。数据基础设施为这些操作提供数据和查询能力，但不会自动完成 Agent 的任务规划。

### 与 MCP

MCP 可以帮助支持该协议的 AI 应用连接外部工具和数据服务。底层数据存储、权限管理和查询逻辑仍需要由相应的系统实现。

## 八、面试准备：需要理解的问题

1. 数据湖和 Lakehouse 有什么区别？
2. 为什么 RAG 需要文档解析和切分？
3. Embedding 与向量检索分别解决什么问题？
4. 向量数据库和数据湖是否可以互相替代？
5. 如何处理更新后的知识文档及其检索索引？
6. 如何兼顾检索效果、查询性能和数据访问权限？

回答这些问题时，应结合具体架构、技术选型和业务场景，而不是只背诵定义。
