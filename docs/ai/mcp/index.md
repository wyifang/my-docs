# MCP（模型上下文协议）

## 一、什么是 MCP？

MCP 是 Model Context Protocol 的缩写，中文通常称为“模型上下文协议”。

它是一种用于连接 AI 应用与外部数据源、工具和服务的开放协议。它帮助 AI 应用以较为统一的方式发现和使用外部能力，减少不同应用与工具之间重复开发专用连接的工作。

**注意：** MCP 本身不是大语言模型，也不等同于 Agent。它主要解决的是 AI 应用如何与外部能力交互的问题。

## 二、为什么需要 MCP？

假设一个 AI 助手需要访问本地文件、查询数据库或调用外部工具。如果每种应用都使用完全不同的连接方式，开发和维护成本就可能增加。

MCP 提供了一套标准化的交互方式，帮助 AI 应用连接支持 MCP 的服务。

它的潜在价值包括：

- 减少重复的集成工作。
- 让工具和数据源以统一的协议形式提供能力。
- 方便 AI 应用发现和调用外部工具。
- 支持不同 AI 客户端复用相应的 MCP 服务。

实际能否复用，仍取决于客户端、服务端和具体功能的兼容性。

## 三、MCP 的主要组成部分

### Host

Host 是承载 AI 交互体验的应用，例如某个 AI 助手或开发工具。

### Client

Client 通常运行在 Host 内，负责与 MCP Server 建立连接，并按照协议交换消息。

### Server

Server 向客户端提供特定能力，例如访问文件、查询数据或调用工具。

可以把它们简单理解为：

- Host：用户使用的 AI 应用。
- Client：应用中负责 MCP 通信的部分。
- Server：对外提供数据或工具能力的服务。

## 四、MCP 可以提供哪些能力？

### Tools（工具）

供 AI 应用发现并调用的操作，例如查询信息或执行某项任务。

### Resources（资源）

向客户端提供可读取的上下文数据，例如文件内容或其他可访问的信息。

### Prompts（提示模板）

由 MCP Server 提供的可复用提示模板，供支持这些能力的客户端使用。

不同客户端对这些能力的呈现方式可能不同。

## 五、MCP 与 RAG、Agent 的区别

### MCP 与 RAG

RAG 关注如何检索相关知识，并把检索结果提供给大语言模型作为生成依据。

MCP 关注 AI 应用如何通过统一协议连接外部数据和工具。

MCP 可以帮助应用连接某些数据服务，但使用 MCP 并不意味着系统一定实现了 RAG。

### MCP 与 Agent

Agent 关注如何围绕目标规划和执行任务，可能会在执行过程中调用工具。

MCP 可以为支持它的 Agent 提供一种连接外部工具的方式，但 MCP 本身并不负责完整的任务规划与决策。

## 六、安全注意事项

接入 MCP Server 时，应关注：

- 服务端是否可信。
- 工具需要哪些权限。
- 是否会读取敏感数据。
- 是否可能执行写入、删除或其他有副作用的操作。
- 如何验证输入、限制权限并记录关键操作。

不要因为某个服务支持 MCP，就默认它安全或值得信任。

## 七、实践练习

设想你正在开发一个 AI 技术文档助手。它需要读取文档、搜索知识库，并帮助用户整理资料。

请思考：

1. 哪些能力适合通过 MCP Server 提供？
2. 哪些功能属于知识检索，可能涉及 RAG？
3. 如果 AI 助手要执行删除文件等操作，应如何控制权限？
4. 为什么不能把 MCP、RAG 和 Agent 当成同一个概念？
