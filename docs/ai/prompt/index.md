# Prompt Engineering（提示词工程）

Prompt Engineering 是指通过设计和优化提示词，引导大语言模型更准确地理解任务，并生成符合要求的结果。

本页面将逐步整理提示词工程的核心概念、设计方法和实践经验。

## 学习目标

完成本主题的学习后，你应该能够：

- 理解 Prompt、指令和上下文的基本概念。
- 设计清晰、具体且结构化的提示词。
- 使用示例、约束条件和输出格式提高结果的稳定性。
- 通过测试和迭代改进提示词。
- 为技术文档编写、知识整理和信息提取设计实用的提示词。

## 核心知识

### 1. Prompt 的基本结构

一个实用的提示词通常可以包含以下要素：

- **角色（Role）**：说明模型需要扮演什么角色。
- **任务（Task）**：明确需要完成什么工作。
- **上下文（Context）**：提供必要的背景信息。
- **约束（Constraints）**：说明限制条件和注意事项。
- **输出格式（Output Format）**：规定结果应该如何组织。

这些要素是帮助组织提示词的常用方法，并非每个任务都必须包含全部要素。

### 2. 提示词优化

设计提示词时，可以重点检查：

- 任务是否明确？
- 背景信息是否充分？
- 约束条件是否具体？
- 输出格式是否清楚？
- 是否需要提供示例？
- 是否通过实际测试验证结果？

## 实践练习

选择一个真实任务，例如总结技术文档。

1. 写出最初版本的提示词。
2. 检查任务、上下文和输出要求是否明确。
3. 修改提示词并再次测试。
4. 比较两次结果，记录改进之处。
