# Agent（智能体）

## 一、什么是 AI Agent？

AI Agent（人工智能智能体）是一类能够围绕目标执行任务的 AI 系统。它可以根据任务需要，结合大语言模型、上下文、工具和执行反馈，完成一个或多个步骤。

与只针对单次请求生成回答的简单交互方式相比，Agent 通常更强调任务规划、工具调用、执行过程和结果检查。

不过，不同系统对 Agent 的定义和实现方式并不完全相同。

## 二、为什么需要 Agent？

假设用户提出一个任务：

“请整理最近更新的产品文档，找出过期内容，并生成一份审查报告。”

一个普通的问答系统可能只会提供建议；具备相应能力的 Agent 则可以尝试将任务拆解为多个步骤，并调用授权的工具完成工作。

例如：

1. 确定需要检查的文档范围。
2. 查询文档的更新时间。
3. 识别可能过期的内容。
4. 汇总检查结果。
5. 生成审查报告。
6. 检查报告是否完整。

这只是一个示例流程。实际系统能否执行这些操作，取决于它拥有的工具、权限和具体实现。

## 三、Agent 的核心组成

### 1. 大语言模型（LLM）

负责理解任务、分析信息、生成计划或决定下一步操作。

### 2. 指令与上下文

提供任务目标、背景信息、执行约束和必要的历史信息。

### 3. 工具（Tools）

让 Agent 能够与外部系统交互，例如搜索文档、查询数据库或调用 API。

### 4. 状态与记忆

用于保存任务执行过程中需要继续使用的信息。不同系统对短期状态和长期记忆的实现方式有所不同。

### 5. 执行与反馈

Agent 根据执行结果判断是否继续、调整方案或结束任务。

## 四、Agent 的基本工作流程

一个常见的简化流程如下：

1. **接收目标**：理解用户希望完成的任务。
2. **制定计划**：把复杂任务拆解为可执行的步骤。
3. **选择操作**：判断是否需要调用工具。
4. **执行操作**：调用获准使用的工具。
5. **观察结果**：读取工具返回的信息。
6. **调整计划**：根据结果决定下一步行动。
7. **检查完成情况**：判断任务是否达到预期目标。

实际 Agent 不一定严格按照这一顺序执行，也可能循环执行、跳过某些步骤，或在需要时请求用户确认。

## 五、Agent 与 Prompt、RAG、MCP 的关系

### Agent 与 Prompt Engineering

Prompt Engineering 用于设计清晰的任务指令、上下文和约束。Agent 可以使用这些提示词来理解目标、规划任务和调用工具。

### Agent 与 RAG

RAG 为 AI 应用提供检索相关知识的能力。Agent 可以在任务过程中使用 RAG 检索信息，但 Agent 并不一定必须使用 RAG。

### Agent 与 MCP

MCP 为支持它的 AI 应用提供连接外部工具和数据源的一种标准化协议。Agent 可以通过 MCP 使用某些外部能力，但 MCP 本身不等于 Agent。

## 六、Agent 的常见风险

- **错误规划**：任务拆解不合理，导致结果不完整。
- **工具调用错误**：选择了不合适的工具或参数。
- **错误信息传播**：把不准确的工具结果当成事实。
- **权限风险**：执行了超出任务需要的操作。
- **无限循环或成本过高**：反复调用模型或工具。
- **结果缺少验证**：任务看似完成，但没有达到真正的要求。

因此，实际系统通常需要权限控制、执行限制、错误处理、日志记录和结果验证。

## 七、实践练习

设计一个“技术文档审查 Agent”，回答以下问题：

1. 用户需要提供什么任务目标？
2. Agent 需要哪些工具？
3. 哪些步骤可以自动执行？
4. 哪些操作需要用户确认？
5. 如何判断最终审查报告是完整且有依据的？
6. 如果工具调用失败，Agent 应如何处理？
